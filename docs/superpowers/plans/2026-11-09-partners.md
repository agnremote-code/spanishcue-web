# SpanishCue Partners Implementation Plan

**Goal:** Ship an integrated B2B acquisition page and prepare a safe operational partner program.
**Architecture:** React/Vinext routes; existing verified owner access; separate D1 partner tables; read-only confirmed billing ledger. Storage readiness gates protect pre-migration releases.
**Tech Stack:** React 19, TypeScript, Cloudflare Workers/D1, existing CSS and brand components.
**Spec:** docs/partners/DESIGN.md

## Global Constraints
US$19.90/month; 30%; first six paid monthly periods; no billing/entitlement mutations; preserve existing subscriptions, campaigns and home; no fake product media or tracking promises.

## Review Focus
- Duplicate/concurrent applications, approvals and settlements must not create duplicates.
- Forged/expired referral cookies and existing/self referrals must not earn commissions.
- Seventh payment, annual/sandbox/legacy payments and reversals must not inflate payable balance.
- Missing storage must produce explicit unavailability, not successful data loss.
- Owner-only data and CSV exports must resist header spoofing, CSRF and spreadsheet formulas.

### Task 1: Storage and domain
Create docs/partners/schema.sql, app/partners/service.ts, db/partners.ts and tests/partners/domain.test.mjs. Test SQL in disposable SQLite including retry, approval, attribution, six-period ledger and settlement balance. Implement integer-cent commission calculations and strict application validation. Migration remains a separately authorized production operation.

### Task 2: Routes and admin
Create /api/partners/apply, /r/partner/[code], /api/admin/partners, /admin/partners. Use existing owner verification and bounded same-origin JSON parser. Add rate limiter. Bind signed cookie at identity-aware requests with failures isolated from checkout. Owner records approved terms, provider reconciliations, adjustments and external settlement reference. Add security/integration tests.

### Task 3: Page and audit
Create /partners metadata, page, scoped responsive CSS, calculator, application form. Reuse official brand/footer and actual demo cover. Exclude teacher acquisition overlays from Partners. Add discreet footer/admin links. Audit public prices against actual constants; preserve #360 overlap and old agreements. Test SSR navigation, metadata, calculator and form behavior; browser desktop/mobile when available. Capture real output.

### Task 4: Delivery
Run domain, security, language, affected billing, TypeScript, full suite/build and artifact validation. Review diff. Commit/push non-draft PR from current main; CI owns merge. Authorize exact additive migration separately before operating the form/program. Follow canonical Cloudflare workflow only after verified main. Report verified state and remaining configuration without claiming unperformed deployment/tests.
